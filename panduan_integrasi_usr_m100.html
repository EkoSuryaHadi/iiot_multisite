Panduan Integrasi Gateway USR-M100

Modbus RTU / TCP to MQTT • Platform IIoT Multisite Architecture

Standard Operating Procedure
Arsitektur Aliran Data:
Sensor/Meter (Modbus RS485) → Gateway USR-M100 → Broker MQTT EMQX (38.47.180.128:1883) → Webhook Auth & Rule Engine → Analytics API & ClickHouse TSDB → Web Dashboard.
1 Registrasi Device di Dashboard Web IIoT

Sebelum menghubungkan gateway fisik, daftarkan perangkat terlebih dahulu pada sistem untuk menerbitkan kredensial otentikasi unik.

  1. Buka dashboard web IIoT Multisite dan masuk ke menu Devices.
  2. Pilih Tenant dan Site lokasi gateway dipasang (misal Tenant: solar, Site: jkt).
  3. Klik tombol + Tambah Device dan lengkapi data:
    • Device Key: Contoh GNIS_MockupUSR (identitas alfanumerik unik tanpa spasi).
    • Nama Perangkat: Contoh Gateway USR M100 - Kantor Jakarta.
  4. Setelah tersimpan di tabel, klik tombol ikon Kunci (🔑) di kolom Aksi untuk melakukan provisioning kredensial MQTT.
  5. Salin informasi yang ditampilkan pada dialog:
    • Client ID: solar-jkt-GNIS_MockupUSR (format: {tenant}-{site}-{device_key})
    • Password: String rahasia kompleks (hanya ditampilkan satu kali saat dialog terbuka)
    • Topic Prefix: t/solar/s/jkt/d/GNIS_MockupUSR
Penting: Password MQTT bukan password akun login web Anda. Password ini adalah secret acak terenkripsi yang di-generate khusus per device. Jika lupa atau hilang, klik kembali tombol Kunci untuk merotasi/menghasilkan password baru.
2 Koneksi Fisik (Wiring & Jaringan) USR-M100
  • Port Ethernet / LAN: Sambungkan port RJ45 USR-M100 ke switch/router lokal yang memiliki akses internet ke IP broker publik (38.47.180.128).
  • Port Serial RS485: Sambungkan terminal A+ dan B- ke slave Modbus RTU (seperti Power Meter, Inverter, atau sensor lingkungan). Pastikan polaritas A dan B tidak terbalik.
  • Power Supply: Gunakan adaptor daya DC 9–36V yang stabil.
  • Akses Web Management: Sambungkan PC/laptop ke jaringan yang sama dan buka browser ke IP default USR-M100 (default: 192.168.0.7, user/pass: admin / admin).

4 Konfigurasi Topik & Format Payload JSON Telemetri

Di menu Modbus to MQTT Data Acquisition pada USR-M100:

A. Topic Publikasi (Telemetry)

t/solar/s/jkt/d/GNIS_MockupUSR/telemetry

* Pola hirarki standar: t/{tenant_slug}/s/{site_slug}/d/{device_key}/telemetry

B. Format JSON Payload

Konfigurasikan template data Modbus agar mengeluarkan format JSON dengan key metrik numerik. Contoh template:

{
  "ts": 1709800000,
  "voltage": 220.5,
  "current": 5.2,
  "power": 1146.6,
  "energy": 128.4,
  "frequency": 50.0,
  "power_factor": 0.98
}
Catatan Karakteristik Ingest:
  • Semua field numerik (voltage, power, dll.) otomatis diparsing dan diagregasi ke ClickHouse.
  • Field ts (Unix timestamp detik) opsional. Jika gateway tidak menyediakan RTC/NTP, server otomatis menggunakan timestamp waktu data diterima broker.

C. Last Will & Testament (LWT) — Pemantauan Status Online/Offline

  • LWT Topic: t/solar/s/jkt/d/GNIS_MockupUSR/status
  • LWT Message: {"status": "offline"}
  • Birth / Connect Message: {"status": "online"}
5 Troubleshooting: Solusi "Connection refused: Not authorized"

Jika saat pengujian koneksi muncul pesan penolakan autentikasi:

Penyebab Gejala Solusi Perbaikan
Password Salah Mengisi password akun web atau password default. Buka menu Devices → klik ikon Kunci (🔑) pada device → salin password baru yang muncul.
Device Nonaktif Device, Site, atau Tenant dalam kondisi dinonaktifkan. Pastikan status perangkat berstatus Aktif di web dashboard. Sistem otomatis menolak koneksi perangkat nonaktif.
Client ID Mismatch Client ID acak (misal mqtt-explorer-xyz). Buka menu ADVANCED di MQTT Explorer/Gateway, samakan Client ID dengan Username: solar-jkt-GNIS_MockupUSR.
Validasi Sertifikat Aktif Opsi "Validate certificate" aktif di port non-TLS (1883). Matikan toggle Validate certificate dan Encryption (tls) pada software client/gateway.
